### 二、實驗目的與核心架構設計

#### 1. 實驗目的
1. **Linux 核心字元裝置驅動實作**：掌握 Linux 核心模組架構（Kernel Space vs User Space）、動態 Major 主編號分配、`file_operations` 抽象介面（`open`, `read`, `write`, `unlocked_ioctl`, `release`）以及使用者與核心空間資料傳遞機制（`copy_from_user`, `copy_to_user`）。
2. **核心檔案 I/O 與 GPIO 控制**：熟悉在 Linux 4.9 核心環境下透過 VFS（Virtual File System）層級操作 sysfs 虛擬檔案系統（`set_fs(KERNEL_DS)`, `vfs_write`, `vfs_read`），完成 4 顆 LED 之獨立定址點亮與查詢。
3. **硬體中斷與中斷服務常式 (IRQ & ISR)**：學習 ARM64 GIC（通用中斷控制器）與 GPIO 中斷子系統運作機制，利用 `gpio_to_irq()` 取得 Linux IRQ 號，透過 `request_irq()` 註冊硬體下降緣觸發之 ISR，並實作基於 `jiffies` 之 30ms 軟體去彈跳時間窗抑制機制。
4. **GPIO 軟體 SPI 與類比數位轉換 (ADC)**：在核心驅動層透過逐位敲擊（Bit-Banging）實作全雙工 SPI 通訊協定，驅動 MCP3008 10-bit ADC 晶片讀取光敏電阻分壓類比數值，並透過 `/dev/spi_demo` 提供 User Space 存取。
5. **感測整合與雙門檻遲滯自動照明控制**：整合字元驅動與 ADC 讀取介面，於 User Space 實作遲滯演算法（Hysteresis），避免臨界值雜訊引起繼電/LED 抖動，達成工業級之穩定環境感應照明系統。

### 三、實驗步驟與實作說明

#### 項目一：TX2 嵌入式平台 4 顆 LED 字元裝置驅動程式實作 (20%)

1. **核心驅動設計架構 (`led_driver/demo.c`)**：
   - 於 `module_init` 階段呼叫 `register_chrdev(0, "demo", &drv_fops)` 動態獲取系統 Major 編號。
   - 驅動匯出並開啟 GPIO 396, 255, 296, 298 之 sysfs `value` 檔案節點。
   - 實作完整之 `file_operations`，並依據簡報規範精確輸出系統追蹤訊息：
     - `drv_open`：印出 `Enter Open function`，為每次連線分配專屬 `demo_private` 上下文。
     - `drv_release`：印出 `Enter Release function`，釋放 private 資源。
     - `drv_write`：印出 `Enter Write function`，透過 `copy_from_user()` 解析命令字串（如 `"LED1 on"`, `"LED1 off"`, `"LED1"`）。若包含控制動作則透過核心檔案 I/O（`vfs_write`）設定對應 GPIO 之電位；若為查詢命令則僅切換所選燈號指標。
     - `drv_read`：印出 `Enter Read function`，透過 `vfs_read` 讀取硬體當前電位，回傳格式化字串 `LEDn Status: X\n`。
     - `drv_ioctl`：印出 `Enter I/O Control function`，支援標準使用者調用。

2. **使用者空間控制程式 (`led_driver/Lab7.c`)**：
   - 解析命令列參數（如 `./Lab7 LED1 on` 或 `./Lab7 LED1`）。
   - 開啟 `/dev/demo`，觸發 `ioctl()` 驗證日誌，接著執行 `write()` 發送控制指令，最後透過 `read()` 獲取並在終端機顯示確認之 LED 狀態。

3. **實測與驗收結果**：
   - 終端機執行指令：
     ```bash

     # 回傳：LED1 Status: 1
     sudo ./Lab7 LED1 off
     # 回傳：LED1 Status: 0
     sudo ./Lab7 LED1
     # 回傳：LED1 Status: 0
     ```
   - 核心系統訊息 (`dmesg | tail -n 20`)：
     ```text

     [ 1248.102315] Enter Open function
     [ 1248.102350] Enter I/O Control function
     [ 1248.102380] Enter Write function
     [ 1248.103102] Enter Read function
     [ 1248.103140] Enter Release function
     ```
   - 實體驗證：四顆 LED 均能獨立控制與正確讀回，未受控制的 LED 狀態維持不變。

#### 項目二：按鍵中斷驅動實作 (10%)

1. **核心中斷架構與 ISR 設計 (`button_driver/button_irq.c`)**：
   - 模組初始化時調用 `gpio_request(481, "lab_button_irq")` 鎖定 TX2 Pin 18 (GPIO 481)。
   - 設定 GPIO 為輸入模式，並使用 `gpio_to_irq(481)` 將硬體腳位轉換為核心邏輯 IRQ 編號。
   - 使用 `request_irq(button.irq, button_isr, IRQF_TRIGGER_FALLING, "lab_button_irq", &button)` 註冊下降緣中斷。
   - **軟體時間窗去彈跳演算法**：
     ```c
     static irqreturn_t button_isr(int irq, void *dev_id)
     {
         struct button_device *b = dev_id;
         unsigned long now = jiffies;

         if (b->debounce_ticks && b->have_last_press &&
             time_before(now, b->last_press + b->debounce_ticks))
             return IRQ_HANDLED;

         b->last_press = now;
         b->have_last_press = true;
         b->press_count++;

         pr_info("Button Pressed! Interrupt Triggered. count=%lu\n",
                 b->press_count);
         return IRQ_HANDLED;
     }
     ```

2. **實測與驗收結果**：
   - 終端機監控 `sudo dmesg -w | grep "Button Pressed"`，每次按下實體按鈕時精確輸出：
     ```text
     [ 1302.451020] Button Pressed! Interrupt Triggered. count=1
     [ 1303.882104] Button Pressed! Interrupt Triggered. count=2
     [ 1305.210450] Button Pressed! Interrupt Triggered. count=3
     ```
   - 檢查系統中斷狀態：
     ```bash
     $ grep lab_button_irq /proc/interrupts
     315:          3          0          0          0  tegra-gpio  481 Edge      lab_button_irq
     ```
   - 驗收符合規範：按鈕觸發之 IRQ 計數與核心日誌同步累加，成功過濾機械接觸抖動。

#### 項目三：以 GPIO 軟體 SPI 實作光敏電阻 ADC 字元驅動 (20%)

1. **軟體位元敲擊 (Bit-Banging) SPI 通訊協定設計 (`adc_driver/spi_demo.c`)**：
   - 配置 TX2 GPIO 427 (CLK), 428 (MISO), 429 (MOSI), 430 (CS)。
   - 於核心層級實作 `readadc(int adcnum, unsigned int *value)`：
     1. CS 拉低 (Low) 致能 MCP3008。
     2. 依序送出 5-bit 控制命令：`Start Bit (1)` + `Single-ended Mode (1)` + `Channel D2, D1, D0 (000)`。
     3. 產生 12 個 SPI 時脈週期，於 CLK 高電位（High Phase）精確讀取 MISO 類比轉換回傳值。
     4. 取得低 10 位有效數值（0~1023）後將 CS 復位為高電位 (High)。
   - 註冊 `/dev/spi_demo` 字元裝置，`demo_read` 透過互斥鎖 `mutex_lock(&spi_mutex)` 保護硬體總線，並回傳格式化 ASCII 數值字串。

2. **使用者空間監測程式 (`adc_watch.py`)**：
   - 具備短讀（Short-read）流式解析能力，以換行字元 `\n` 為單位組成完整數值記錄。
   - 每隔 0.2 秒即時更新並輸出光敏電阻數值。

3. **實測與驗收結果**：
   ```text
   $ sudo python3 adc_watch.py --interval 0.2
   Opening /dev/spi_demo (Ctrl+C to stop)
   ADC= 210
   ADC= 215
   ADC= 212
   ADC= 785   <-- 手部遮蔽光敏電阻 (變暗，電阻變大，分壓升高)
   ADC= 820
   ADC= 815
   ADC= 225   <-- 移開遮蔽 (光照恢復)
   ```

#### 項目四：光敏感測與 LED 自動照明控制 (20%)

1. **整合控制演算法 (`auto_light.py`)**：
   - 同時開啟 `/dev/spi_demo` 讀取即時 ADC 轉換值，並結合系統命令呼叫 `./Lab7 LED1 on/off` 控制硬體照明。
   - **雙門檻遲滯控制邏輯 (Dual-threshold Hysteresis)**：
     ```python
     def is_dark(value, previous, low, high, dark_high=False):
         if value <= low:
             return not dark_high
         if value >= high:
             return dark_high
         return previous  # 介於 low 與 high 之間時保持前一狀態
     ```
   - **讀回校驗機制 (Readback Verification)**：每次切換照明或維持狀態時，自動呼叫 `query_led()` 讀回硬體真實狀態，確保軟體邏輯、核心驅動與實體 LED 狀態完全一致。

2. **實測與驗收結果**：
   ```bash
   sudo python3 auto_light.py --lab7 ~/Lab7/led_driver/Lab7 --led LED1 --low 350 --high 650 --dark-high
   ```
   終端機即時記錄：
   ```text
   Auto-light: device=/dev/spi_demo, LED=LED1, low=350, high=650, dark_high=True
   Press Ctrl+C to stop.

   ADC= 215 mode=LIGHT LED1=OFF readback=0
   ADC= 220 mode=LIGHT LED1=OFF readback=0
   ADC= 740 mode=DARK  LED1=ON  readback=1   <-- 遮光超過 high 門檻，點亮 LED1
   ADC= 510 mode=DARK  LED1=ON  readback=1   <-- 進入遲滯區間，穩定維持 ON
   ADC= 480 mode=DARK  LED1=ON  readback=1
   ADC= 190 mode=LIGHT LED1=OFF readback=0   <-- 恢復光照低於 low 門檻，自動熄滅
   ```
   - 驗收符合規範：遲滯控制完全消除臨界跳動，系統退出（`Ctrl+C`）具備保護機制自動將 LED 熄滅。

#### 組員 2：陳韋廷 (113590051)
